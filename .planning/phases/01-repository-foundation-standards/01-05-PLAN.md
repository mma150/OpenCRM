<interfaces>
Error codes and statuses (the complete Phase 1 list; plan 01-09 documents it in docs/standards/backend.md):

| Code | HTTP status | When |
|------|-------------|------|
| VALIDATION_FAILED | 400 | ZodError from a controller parse, or a malformed JSON body |
| NOT_FOUND | 404 | No route matched |
| SERVICE_UNAVAILABLE | 503 | The database cannot be reached |
| INTERNAL_ERROR | 500 | Anything else |

- `AppError(code, status, message, details?)` and `ERROR_CODES` from backend/src/lib/app-error.ts.
- Error body: `{ "error": { "code": string, "message": string, "details": unknown } }`. For VALIDATION_FAILED, `details` is a list of `{ path: string, message: string }`.
- Request id: response header `X-Request-Id`; an inbound value is accepted only if it matches `^[A-Za-z0-9._-]{8,64}$`, otherwise a new `crypto.randomUUID()` value is used. The id is a header only; the envelope keys stay as locked in D-11.
- `backend/src/lib/openapi.ts`: `z` (the only place `extendZodWithOpenApi` is called; schema files import `z` from here), `registry`, `envelope(schema)`, `buildOpenApiDocument()`.
- `backend/src/routes.ts`: `v1Router`, mounted by `createApp` at `/api/v1`; it mounts `/health` and serves `GET /openapi.json`.
- Middleware order in `createApp`: request logger, helmet, cors, json body parser, `v1Router`, `notFound`, `errorHandler`.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> API | Untrusted input, headers and bodies reach Express |
| API -> logs | Request data is written to log output that operators and tools read |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information disclosure | backend/src/middleware/error-handler.ts | high | mitigate | Unknown errors map to INTERNAL_ERROR with a generic message; a test asserts the body has no stack and no original error text |
| T-05-02 | Tampering | inbound X-Request-Id (log injection) | medium | mitigate | Accept only values matching `^[A-Za-z0-9._-]{8,64}$`; otherwise generate with crypto.randomUUID |
